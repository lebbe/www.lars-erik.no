MISSION BRIEFING

GITOPS · ISSUEOPS

Two words keep getting thrown at you. Here's the whole philosophy in one breath: stop clicking buttons, start declaring intent.

GitOps

Git is the single source of truth. You don't change infrastructure by poking a portal — you change a file, open a pull request, merge it, and a robot (an "operator") makes the real world match the file. The repo describes desired state; reality is just a cache of the repo.

IssueOps

You drive operations from GitHub Issues & comments. Type a slash command, a GitHub Action fires, the work happens, and the issue thread becomes your audit log + approval record. ChatOps' tidier, paper-trailed cousin.

FRONTEND TRANSLATION You already live this. In React you don't manually append DOM nodes — you declare what the UI should look like and let the reconciler diff & patch. GitOps is React's render() for your entire cloud: declare the desired state, let automation converge reality to match.

AZURE: THE LAY OF THE LAND

CLOUD TOPOLOGY

Before you touch anything, learn the nesting dolls. Everything in Azure lives inside a strict hierarchy. Tap a layer to drill in.

portal.azure.com — resource explorer

Entra ID

Formerly "Azure AD". The identity layer — it decides who you are. Every login, every service principal, every managed identity is registered here. PIM (module 03) lives inside it.

RBAC

Role-Based Access Control = who can do what, where. A role assignment binds a principal + a role + a scope. Reader, Contributor, Owner are the classics. Scope can be a subscription, a resource group, or one resource.

KUBERNETES (AKS)

ORCHESTRATION

The scary one that isn't. AKS = Azure's managed Kubernetes. The core idea is gloriously simple once you see the trick.

FRONTEND TRANSLATION — this is the whole game Kubernetes is React for infrastructure. You don't imperatively "start a server". You write a Deployment that says "I want 3 replicas of this container" — that's your desired state, like JSX. A control loop constantly diffs desired-vs-actual and patches reality. Kill a pod? It notices the diff and re-renders a new one. You never manage the steps, only the destination.

The vocabulary

Node = a worker VM. Pod = smallest unit, wraps your container(s). Deployment = keeps N pods alive. Service = stable address + load balancing. Namespace = isolation walls. kubectl = the remote control.

The reconciliation loop

desired state → controller observes actual → computes diff → acts to close the gap → repeat forever. Self-healing falls out of this for free. Crashes, evictions, node death — the loop just keeps re-converging.

PIM — PRIVILEGED IDENTITY MGMT

JUST-IN-TIME ACCESS

The single biggest source of "but I have permission, why is it 403?!" confusion. Learn this and you'll out-debug half the team.

The big idea: nobody walks around with admin powers all day. You're eligible for a role — not permanently holding it. When you need it, you activate it just-in-time (justification, MFA, sometimes approval), and it auto-expires.

Entra ID — PIM // role: Contributor @ rg-genesys-prod
Contributor — scope: rg-genesys-prod

Assignment present in policy. Eligible ≠ active.

⚠ THE 403 TRAP Your role assignment can look perfect in the portal / get-iam-policy output and you'll still get 403 — because it's eligible, not activated. Permissions present ≠ permissions active. When access mysteriously fails and the bindings look right, check PIM activation first. (Same trap bites JIT bindings on the GCP side.)

SECRETS

Secrets, keys and certificates live in the vault — never in your code, never in your repo. Your app proves who it is, and the vault decides whether it hands over the secret. Pick how your app authenticates, then deploy. Choose wisely.

GITOPS IN PRACTICE

DRIFT CONTROL

The daily loop: edit YAML → open PR → get review → merge → operator reconciles. Git is truth; the live cluster is a cache of git. Hand-edit the cluster and an operator will revert your change — that's drift detection, and it's a feature.

The drift lesson

Manual changes don't survive. The operator continuously diffs the cluster against git and squashes anything that doesn't match. If you "fixed prod" in the portal at 2am, congratulations — it'll be gone by the next reconcile.

Get the YAML right the FIRST time

PRs to infra repos often need a separate platform/drift team's approval. Roundtrips are expensive. Copy an existing reference manifest as a template, match the house style, and submit it clean.
